## 可继续加深的 10 个维度

### 1. 设备运行时（Device Runtime）— 优先加深

- 连接/断开/重连、`ResourceId` 与 UDL 通道生命周期
- 能力目录扩展（电源、温控、串口仪表…按公司真实设备加）
- 统一命令审计（谁、何时、下了什么、结果码）
- 多设备并行 vs 同资源串行策略（你们已有 executor 种子，可产品化）
- 故障注入 Simulator（超时、断线、坏值）逼出健壮性

### 2. 上下行数据面（Tag / Telemetry）— 强烈建议下一块

- 下行：`Command`（写设定、点按钮）
- 上行：`Tag` 流（周期采集 / 事件推送），Debug 与工位看板共用
- 单位、量程、坏点、质量戳（Good/Bad/Stale）  
 没有这一层，UI 再好看也只是「按钮调 Proxy」。

### 3. Workflow / 工艺编排 — 从空壳到可用

- 显式 Step 列表（名称、超时、可重试、失败策略）
- 互锁（条件不满足禁止 Start）
- Recipe/Spec 外置（阈值不进 UI）
- 运行轨迹：当前步、已用时、步骤日志事件 → 绑 UI  
 仍建议自建薄模型，不要上 LabVIEW/Elsa。

### 4. 数据与追溯（Data Pipeline）

- `SessionId`、SN、操作员、Recipe 版本
- 本地先存（JSON/SQLite）→ Pending 上传
- PASS/FAIL 判定与测量有效性  
 这是「生产上位机」和「调试玩具」的分水岭。

### 5. 工位壳 UI（Shell）— 精美但不低代码

- 标准控件：状态灯、报警条、步骤条、Tag 表、命令栏、日志
- 主题/布局资源字典（复制 App 即带壳）
- Debug Console 增强：自动刷新、趋势、批量读写  
 配置化半低代码（JSON→控件）放在有 2+ 真实工位之后。

### 6. 报警与安全

- 报警定义、确认、锁存、与 Fault 的关系
- 急停/安全门类互锁接口（即使先 Simulator）  
 产线 HMI 的必备维度，现在完全空白。

### 7. 配置与多环境

- Simulator / Real 分层配置、热加载边界
- 工位参数与设备表分离
- 配置校验（启动时 fail-fast）

### 8. 集成出站（MES/TAS/文件）

- `IUploadGateway` + Simulator
- 幂等、补传、超时（这里以后才值得考虑 Polly）  
 无真实对接需求前只留接口。

### 9. 工程化与「快速搭工位」

- `New-Station.ps1` / `dotnet new` 模板
- 一键 publish、版本号、日志目录约定
- CI（build+test）、架构/分层分析器  
 平台「浅」的另一面往往是：复制成本还不够低。

### 10. 可观测与运维

- 结构化日志、运行 ID、性能计数（步耗时、设备 RT）
- 健康仪表板（全设备 Health 一览）
- 现场排障包（配置快照 + 最近 N 条命令）

---

## 建议推进顺序（避免摊大饼）

```
P3  Tag 上下行 + 周期采集（数据面）
P4  Workflow Step 模型 + 步骤 UI 绑定
P5  Session 本地落盘（追溯最小集）
P6  Shell 控件库 + Debug 自动刷新/趋势
P7  报警/互锁
P8  出站适配 + 工程化模板
```

刻意往后放： LabVIEW 级随意搭 UI、通用运动/视觉、一次对接所有 MES。
